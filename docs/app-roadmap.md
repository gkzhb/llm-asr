# 通用 Android App 路线图（当前优先级）

本文件按用户最新要求调整后续实施顺序，**优先于旧实施规划中的天玑1000+优化安排**。旧数值基线、问题和证据不删除；最小源码检查点为 `89d244a`。

## 1. 目标与非目标

先成为在不同厂商ARM64手机上可用、可诊断、尊重隐私的离线转写App，再做IME/API。不是先围绕某一SoC追求跑分。

- 第一支持范围：Android10/API29+、64位Android/arm64-v8a、MNN CPU。骁龙、天玑、Exynos、Tensor等为测试对象，不以品牌白名单拒绝设备，也不因CPU名字自动开启未经验证的后端。
- 8GB RAM以上建议保持；不是“8GB保证可运行”或“6GB绝对不支持”。可用内存、录音时长和系统回收政策都影响结果。保留现有1.57GB模型和约3.1GiB历史原生PSS作为容量参考，不伪装新版最坏值。
- 不强行支持32位/x86，不把arm64构建通过等同全部SoC/固件已验证。4KiB/16KiB页设备都需安装/运行测试；链接对齐只是静态门槛。
- 暂缓：天玑专属绑核/频率策略、Mali优化、APU/QNN/Hexagon、厂商NPU、GPU默认启用。
- 后续优先跨设备收益：生命周期/内存释放、分段、加载复用（验证会话隔离后）、量化（保持正确性门槛），不以取消质量验证换速度。

## 2. 交付顺序与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| A / 0.2 前台短句录音 | 请求权限、录音时间、停止并转写、取消、30秒限制；保留示例和WAV导入 | 权限拒绝/撤销可恢复；无麦克风设备仍可文件转写；用户离开界面不继续录音；不把录音失败/取消当结果；真实录音待设备测试 |
| B 模型与结果管理 | 模型准备状态、进度/存储提示、删除确认；编辑/分享/导出结果；历史默认不自动保存私人音频 | 中断导入不发布半份模型；失败/取消与历史成功区分；文本与录音可删除；保持固定清单验证 |
| C 生命周期与通用性能 | 独立任务/服务状态、可靠中止、可选短时模型驻留、设备诊断导出（不含音频/正文默认） | 旋转/锁屏/切后台/低内存/重复请求/不同语言不串数据；服务策略按目标Android权限验证 |
| D 长音频与VAD | AudioExtractor/MediaCodec解码常见格式、单声道重采样、限额分段、静音门控 | 长输入有界，取消和失败保留分段状态；重复/边界漏字回归；VAD参数有真实语料，不把能量阈值冒充可靠VAD |
| E 系统输入法 | 用户手动启用，预览/确认提交，输入框切换保护 | 过期任务不能提交到新输入框；密码/敏感输入保护；不自动修改系统默认输入法 |
| F 本机API | 共享单推理引擎的Binder/AIDL、调用者权限与资源限额 | 未授权调用拒绝、并发受控、请求身份/取消隔离；HTTP默认不实现/不开启，单独安全里程碑 |

A先交付，B–F不在一版堆叠，避免把生命周期/内存风险带进IME。

## 3. 0.2录音范围

- 仅用户在前台点击“开始录音”并授予 `RECORD_AUDIO` 后使用标准Android `AudioRecord`。
- 首版明确要求系统可提供16kHz单声道PCM16录音；不支持时显示错误并保留WAV入口，不盲目把48kHz数据按16kHz写入。多采样率回退另设测试后实现。
- 最长30秒，按实际样本数封顶；显示时长；停止后转写；取消/离开界面丢弃尚未转写的采集数据并释放麦克风。
- 不后台监听、不注册开机录音、不自动授权；无网络权限。AudioRecord初始化/读取失败、资源被其他App占用、一次性授权失效都必须释放资源。
- 仍每次加载模型、非流式、无可靠VAD。安静/噪声可能有幻觉输出；不要用于自动提交输入框。
- 不在本轮自动采集手机麦克风；模拟PCM测试/构建不能替代用户真实硬件验收。

### 0.2 录音生命周期的精确边界（审查修正）

启动、取消和转写交接使用同一会话同步gate。取消先获gate时禁止再启动麦克风或发布WAV/转写任务；启动先获gate时，取消在启动调用结束后生效，由采集worker停止并释放。采集循环不持锁。硬件启动调用可能延迟UI取消回调，因此不能承诺onPause返回之前麦克风已同步释放；取消到系统录音指示消失的延迟必须实机测量。

采集释放后先竞争一次转写提交：取消先赢则丢弃；提交先赢则进入不可取消的native推理，后续取消返回“不接受”，不伪装已取消。onPause通过同一gate锁存取消，后续回前台不会复活已取消会话。停止按钮不是取消，可以正常转写。

系统麦克风开关或录音争用有时会返回静音而非错误；当前无数据超时不等同静音检测，不能保证识别这类情况。VAD及设备测试仍待后续验收。

用户反馈重构版“验证没问题”，随后明确要求先实现输入法。因此本节覆盖上文交付顺序：**首版语音IME → 模型管理增强 / 生命周期诊断 → 长音频与后续API**。版本`0.4-ime-debug`用于首版IME，原“0.4模型管理”延期，不因版本号推进而视为已实现。
