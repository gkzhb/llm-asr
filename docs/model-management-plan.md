## 1. 目标、范围与非目标

### 用户目标

在一个独立的“模型管理”页面，能回答：**装了什么、是否能用、占多少空间、现在进行到哪、出错怎么恢复、不用了怎么删除**。转写主页只负责录音/文件转写及结果，输入法继续负责语音输入，不承载大文件操作逻辑。

### 本版必须交付

1. 独立完整页面、主页入口、输入法入口和返回路径。
2. 模型信息、文件完整性、校验状态、内部存储占用展示。
3. 用户选择目录导入、逐阶段/逐文件进度、协作取消。
4. 文件级重试复用、损坏修复、空间不足/权限/文件异常提示。
5. 确认删除内部模型，准确报告部分失败与剩余文件。
6. 模型维护与转写结果分离；App、IME、模型操作仍共享一个任务owner。

### 不在本版

- 在线下载、模型商店、多模型切换、自定义清单/配置路径、导入压缩包或原始safetensors。
- 量化、GPU/NPU、模型常驻、转写提速、长音频/VAD、API。
- 单文件字节级断点续传、后台服务/后台下载保证、自动重试/自动删除。
- 重写全App UI框架、引入Compose/Gradle迁移或历史数据库。
- 额外独立文件详情页面：首版详情在模型管理页面展开即可。

## 3. 页面结构与导航

### 3.1 页面技术形式

新增 `ModelManagementActivity`，作为**独立Activity页面**，不是弹窗、主页新增一排按钮或输入法内嵌页。

- 与App/IME同进程，`android:exported="false"`，无外部intent-filter。
- 顶部返回标题栏、可滚动内容区、明确操作区；无新底部导航体系。
- 不透明浅色页面，深色文字与可辨识禁用态；适配系统栏/insets，不遮挡底部按钮。
- 点击区域至少48dp，文字使用sp，支持大字体/小屏/横屏滚动；状态有文字，不只靠红绿颜色。
- 文件hash、长文件名可换行/展开；进度播报节流，不能每读取块都触发TalkBack公告。

### 3.2 入口与返回

**转写主页**
- 用“模型：已就绪 / 未安装 / 待校验 / 处理中”的摘要卡替代原三个模型操作按钮。
- 卡片有一个“模型管理”按钮；主页状态更新不覆盖识别正文。
- 任务执行时仍可打开页面查看状态，但写操作必须通过真实owner检查，不能靠按钮禁用充当锁。
- 从主页录音进入管理页前，提示先停止或取消录音；不默默中断用户录音。

**输入法**
- 增加明确“模型管理”入口，不在键盘直接导入/删除。
- 复用现有安全离开流程：使当前输入会话/预览作废，取消尚未交接的采集，请求隐藏键盘，再显式打开Activity。
- 已进入处理阶段只能等待，管理页显示“输入法正在处理，完成后可管理模型”。
- 页面返回后由用户重新选择/显示输入法；不保存旧InputConnection，不自动恢复录音或提交。

**首次/缺模型**
- 主App与IME错误提示指向模型管理页，带原因码即可，不携带正文/私人音频URI。
- 打开管理页面本身不请求麦克风、不弹文件选择器、不读外部目录、不加载模型。

## 4. 状态模型与按钮矩阵

**模型状态与任务状态分开**，不能把“上次操作失败”直接当成“现有模型损坏”。“文件检查通过”也不等同本机推理/性能已验证。

### 模型状态

| 状态 | 含义/页面提示 |
|---|---|
| UNKNOWN | 正在读取内部文件概况，未取得可靠快照 |
| NOT_INSTALLED | 清单文件和受管残片均不存在 |
| INCOMPLETE | 缺文件、大小不匹配或只有残片；显示具体文件 |
| UNVERIFIED | 文件外观完整，本进程当前模型epoch没有全量SHA成功证据 |
| READY | 固定清单全部大小/SHA通过且epoch未失效；“文件已校验，可尝试转写” |
| INVALID | SHA不符或存在非法目录/链接等，禁止就绪 |

任务状态独立为 `IDLE / INSPECTING / ENUMERATING / CHECKING_EXISTING / COPYING / VERIFYING_FILE / PUBLISHING / FINAL_VERIFY / DELETING / CANCELLING / SUCCEEDED / CANCELLED / FAILED`。终态必须携带operationId、类型、结果与清理结论。

| 场景 | 导入/修复 | 完整校验 | 取消 | 删除 | 页面查看/返回 |
|---|---|---|---|---|---|
| 未安装且空闲 | 可用 | 禁用 | 隐藏 | 无受管文件则禁用 | 可用 |
| 不完整/未校验/损坏且空闲 | 可用 | 有完整文件时可运行并报告问题 | 隐藏 | 有受管文件可用 | 可用 |
| 就绪且空闲 | 可用，优先复用不重复复制 | 可用 | 隐藏 | 可用，需确认 | 可用 |
| 本页导入/校验中 | 禁用 | 禁用 | 可用 | 禁用 | 返回需结束操作策略 |
| 发布文件短临界区 | 禁用 | 禁用 | 记录请求，等临界区结束生效 | 禁用 | 不阻塞主线程 |
| 正在取消/收尾 | 禁用 | 禁用 | 禁用，显示正在取消 | 禁用 | 可离开，owner仍占用 |
| 删除中 | 禁用 | 禁用 | 不提供撤销/取消 | 禁用 | 可离开，继续短删除收尾 |
| App/IME占用owner | 禁用并说明来源 | 禁用 | 不能取消他人任务 | 禁用 | 可查看已有快照，不并行扫磁盘 |

## 5. 逐项功能契约

### MM-01 内部状态与存储检查（P0）

- 页面首次显示轻量读取内部清单文件的存在性、大小、受管残片；**不自动计算1.57GB的SHA**。
- IO走共享owner和worker；主线程只渲染快照。占用时显示缓存状态与“等待其他任务完成”，不展示伪实时存储数据。
- 分开显示：预期模型大小、现有正式文件字节数、残片字节数、文件系统可用空间。
- “逻辑文件大小”不是磁盘物理分配量，“可用存储”不是可用RAM，“删除可释放”只能估计；删除后重新查询空间，不承诺精确增量。
- 初始状态/导入结束/删除结束/重新进入页面后刷新；刷新不写转写报告。
- 当前进程可用性由共享模型状态统一维护；既有推理懒校验也必须通知同一状态，不能UI说未校验而引擎另存一个true。

### MM-02 选择目录与导入预检（P0）

1. 用户点击选择目录，使用SAF `ACTION_OPEN_DOCUMENT_TREE`，仅请求读权限。
2. 选择器等待期不持owner；取消选择不改模型、结果或已有校验结论。
3. 用单pending请求身份校验回调；旧Activity/重复/失效回调不得启动导入。首版重建后无法可靠归属的回调拒绝并提示重新选择。
4. 回调后先取得owner，再枚举专用目录与检查本地文件；其它任务抢先启动则明确拒绝，不隐式排队。
5. 仅导入固定清单名称；忽略无关普通文件，拒绝重复名称/超过10000条目/非法条目；不递归、不解压、不信任外部配置中的路径。
6. 校验现有完整文件，计算本次可复用集合与缺失/损坏集合；所需源文件缺失时，在开始复制前报告。全部本地文件已正确时允许直接最终核验，不要求重拷。
7. 外部文件大小/名称是提示信息，最终以受控字节读取上限、实际长度、SHA为准；云provider可能联网取文件，界面提示优先使用本地目录。App本身不新增INTERNET权限。

### MM-03 空间预算、复制与发布（P0）

- 在owner内先安全回收已确认的受管孤立part，再计算/检查空间；失败不能忽略后继续。
- 预检保守估计：`sum(本次需重新复制文件的完整预期大小) + 64MiB余量`。不预先扣除未来可能被替换的损坏文件大小；这可能偏保守，但不会把未来释放当成当前可用。
- 每文件开始前仍检查 `文件完整预期大小 + 64MiB`；可用空间会被系统/其他应用改变，预检通过不是写入成功保证。
- 顺序单worker、固定有界缓冲区（沿用1MiB），不能一次加载大权重到Java内存。
- 同目录`文件名.part`写入，流成功关闭，再检查长度和SHA；都成功后才能原子rename到正式文件名。
- 未完成或不匹配part不得作为可用模型；不先删除正确正式文件来腾空间；损坏旧副本仅在新part成功发布时替换。
- 每文件原子发布不是七文件总事务或断电持久性保证。最后仍执行全清单校验，成功提交READY前再检查取消与模型epoch。

### MM-04 进度口径（P0）

采用**阶段化进度，不使用含糊的单一安装百分比**：

| 阶段 | 展示与计算 |
|---|---|
| 枚举/回收/规划 | 不定进度，显示阶段；不能编造百分比 |
| 检查可复用文件 | 已读取校验字节/本阶段待检查字节；文件数只是辅助 |
| 复制 | 当前文件已写/预期；本次需复制总量累计已写/预检确定总量；复用字节另列，不算新复制 |
| part校验 | 当前part已读/文件总量；与复制百分比分开 |
| 发布 | 短不定阶段，不提前显示成功 |
| 最终核验 | 已读取/全清单字节总量；仅全量完成才进入成功 |
| 删除 | 已处理受管文件数/计划文件数；同时显示失败数，不能按时间伪造进度 |

- 每个阶段内部进度单调、有界；阶段切换允许重置，但阶段标题同步改变。
- 复制100%时必须显示“复制完成，仍在校验”，不能显示“安装完成”。
- UI刷新建议不超过每秒5次，终态立即通知；此为实现目标，非已测延迟。
- 默认不展示估算剩余时间，避免provider抖动造成错误承诺。

### MM-05 完整校验（P0）

- 用户主动触发全文件长度/SHA检查，可取消，并显示读取进度。
- 校验开始使本次结果标为进行中；保留“上次校验”仅作历史，不能在本次失败后仍视为READY。
- 校验成功将全部7文件状态更新为通过；失败精确标记文件/类别。
- 取消校验保守回到UNVERIFIED（若存在已确认缺失/损坏则保持对应状态），禁止把部分校验结果作为完整可用证明。
- 进程重启后即使记录过成功时间，也只显示“上次通过，本次尚未校验”。不要持久化true后直接跳过SHA。

### MM-06 协作取消与完成竞态（P0）

- ModelOperationControl独立于RecordingControl，按operationId绑定；UI取消只能命中自己的模型任务。
- 检查点：枚举前后/遍历条目、每个复制或hash块前后、下一个文件前、文件发布前、全量成功提交前。
- UI取消只锁存请求，不跨线程close provider流或interrupt假装IO已停止；worker负责关闭/清理。
- 外部query/read/close可能阻塞；显示“正在取消，等待文件读取结束”，不超时释放owner、不启动第二个写任务。
- 文件发布与取消需有明确原子次序：取消先赢则不发布本文件；发布先赢则保留已校验文件，在后续边界停止。不要持UI可等待的锁跨长IO。
- 成功提交与取消也需仲裁：最终成功先赢则返回“已完成，无需取消”；取消先赢不得随后发布SUCCEEDED/READY。
- 取消后的清理失败独立显示：操作已停止，但有残片待处理；不得声称“已全部清理”。

### MM-07 重试/修复（P0）

- 本版不持久化外部目录访问授权/完整URI。重试按钮写明“重新选择目录并重试”；选择完后复用已校验的正式文件。
- 取消/进程退出后保留已发布的正确文件；未完成单个part不从字节偏移继续，先受限回收再重拷。
- 不自动发起重试，不回放旧Activity选择结果，不删除外部源文件。
- 模型文件变更前递增modelEpoch并撤销旧READY，任务成功仅可提交本epoch结果。若预检尚未改文件就失败，可保留与同epoch一致的已有有效READY。

### MM-08 删除内部模型（P0）

确认文案：
> 删除本应用内部模型副本及未完成导入文件？预计释放约 X。删除后App和语音输入法需要重新导入模型。不会删除你选择的外部源目录、转写文本或导出文件；删除不是安全擦除。

- 对话框只表达意图，不长时间占owner。确认后重新取得owner，复核modelEpoch和受管清单；模型已改变则刷新并要求重新确认，忙则拒绝，不排队等待后偷偷删除。
- 删除前使模型不可用并递增epoch；与任何App/IME录音/推理/导入/校验互斥。
- 仅删除内部固定根目录下清单文件及它们的明确part名；拒绝符号链接/路径逃逸，不递归目录、不删除未知文件、不扩大ResultFiles的结果清理范围。
- 删除为短的逐文件操作，不提供伪“撤销”；不在本版承诺中途取消。普通删除失败尽量收集剩余受管文件错误；遇到非法根/路径边界立即停止。
- 部分删除失败显示“部分删除：成功N项，失败M项，仍占用约X”，状态不可READY。提供“重试删除”（再次确认），不能直接显示未安装。
- 未知文件保留并提示；只有空且确认安全的模型目录才可删目录本身。UI区分“受管模型已删除”与“内部目录仍有未管理文件”。
- 删除不清App正文、raw报告、编辑结果、剪贴板、外部TXT；IME未提交预览不因模型删除被当成新推理结果，现有会话失效保护维持。

## 6. 生命周期、任务隔离与结果保护

### 推荐首版策略：前台管理，不提供后台持续保证

- **旋转/配置重建**：任务绑定进程，不绑定旧Activity；新页面观察当前operationId，无重复任务。弱引用监听、主线程渲染、owner释放后重新计算按钮。
- **返回/显式离开管理页（导入/校验中）**：提示“留在页面”或“取消并离开”。后者发取消请求后可离开；收尾仍持owner，主页/IME显示等待。
- **Home、锁屏、切其他App**：管理Activity的非配置离开触发本页导入/校验取消，不承诺后台继续。回前台显示取消/收尾状态，不自动恢复。
- **系统文件选择器**：等待选择时尚未启动模型IO，不把打开选择器误判为取消正在执行的导入。选择回调只在恢复前台并归属有效请求时处理，否则拒绝或暂存到有效onResume一次处理，禁止后台自动开始。
- **删除已确认开始**：离开页面仍允许短删除尝试和状态收尾，不回滚，进程kill后下次检查真实文件。
- **进程被杀**：没有“继续后台任务”保证；重开重新检查，回到缺失/未校验状态，用户主动重试。受管part只在持owner的维护/重试中回收。
- 不添加ForegroundService/唤醒锁/自动重启；管理页自身长操作可使用已有KEEP_SCREEN_ON模式，页面离开解除，不宣称可防系统回收。

### 结果隔离硬约束

模型管理状态不使用App转写状态字符串充当唯一模型状态源，不调用旧会清正文/写ASR报告的MODEL_OPERATION默认路径。

优先复用现有RequestRunner：为模型操作提供私有State与无ASR Reports端口、MAINTENANCE策略；明确取消文案需模型化，不能显示“已取消录音”。必要时给runner增加默认保持原行为的取消状态策略参数，并回归App/IME调用。不要为了几个字符串复制整套runner。

本版最近模型操作终态先保存在进程内快照，不新增模型日志数据库或将模型操作写入`last-result.json`。跨进程只重新检查真实文件；以后如需持久化校验时间，另加版本化元数据，且不能作为免SHA凭证。

## 7. 建议组件划分与代码落点

名称为建议，实施时保持最小改动；不要求照搬所有类名或增加不必要抽象。

| 组件 | 职责 | 禁止 |
|---|---|---|
| ModelManagementActivity（新增） | 页面构建、SAF选择、确认弹窗、观察状态 | 直接hash/复制/delete、持有工作线程闭包 |
| ModelManagementController/Operation（新增） | 校验入口、任务准入/取消、重试/删除事务 | 新建第二owner/执行器、写ASR正文 |
| ModelManagementState/Snapshot（新增） | 模型状态、operationId/epoch、阶段、文件进度、错误 | 存Activity/私人音频/IME正文 |
| ModelOperationControl（新增） | 同请求取消/发布/终态仲裁 | 混用录音gate、提前释放共享锁 |
| ModelRepository（扩展） | inspect/verify/import/delete受控文件算法 | Android UI依赖、任意目录递归删除 |
| ModelSource/SafModelSource（扩展） | 有界枚举/读取，传递取消检查边界 | 相信来源hash/路径、读取用户未选择目录 |
| AppGraph/AppState（小改） | 注入同进程组件、统一模型可用性 | 保留两套不一致verified |
| MainActivity/AsrImeService/ImeBackend（小改） | 入口/摘要/统一模型状态消费 | 修改JNI数学、录音/提交安全语义 |
| Manifest/构建脚本/测试 | 新Activity非exported、源码/资源指纹、版本5 | 放开网络/存储权限白名单 |

快照建议字段：`modelId, manifestDigest, modelEpoch, readiness, activeOperationId, operationKind, phase, fileName, fileIndex, fileCount, fileBytesDone/Total, stageBytesDone/Total, reusedBytes, installedBytes, orphanPartBytes, availableBytes, lastOutcome, errorCode, failedFiles, cleanupOutcome`。

所有字段都定义未知值，不以0伪装未知。界面以不可变快照渲染，迟到进度按operationId/epoch过滤；大量进度更新不不断追加日志。

## 8. 错误提示与恢复动作

| 错误 | 用户文案重点 | 可执行恢复 |
|---|---|---|
| 源目录缺文件/名称不对 | 列缺失名，提示需MNN部署目录不是原始权重 | 重新选择目录 |
| 重复名/条目超限 | 目录不符合要求，未继续导入 | 使用专用本地目录 |
| 外部权限失效/读取失败 | 无法读取所选文件；不输出完整URI/私人路径 | 重新选择并授权；换本地源 |
| 空间不足/写入失败 | 当前可用与本次保守需求，说明已保留哪些完整文件 | 用户在系统释放空间后重试，不自动删数据 |
| 文件过短/过长/SHA失败 | 具体文件与错误类别，不发布坏part | 换正确源文件后修复 |
| 原子替换/close失败 | 导入未完成；旧已验证文件不主动删除 | 重试，必要时检查空间/存储 |
| 清理或删除失败 | 列失败受管名和剩余空间，不能报全成功 | 重试清理/删除，仍需owner与确认 |
| 其他任务忙 | “输入法/应用正在处理，请稍候” | 等待，不能取消其他任务 |
| 取消等待IO | “正在取消，等待文件读取结束” | 等待/离开；不提供危险强制并发按钮 |

## 10. 分阶段实施与交付门槛

| 阶段 | 交付内容 | 完成门槛 |
|---|---|---|
| M1 页面骨架与状态分离 | 独立Activity、主页/IME入口、存储/文件详情、原导入校验入口迁移、转写结果保护 | Android编译与导航可运行，模型操作不清结果；不声称此时已有取消/删除 |
| M2 可取消的导入/校验 | typed进度、控制令牌、空间预检、完整文件复用、错误恢复、前台生命周期策略 | 生产组件发布/取消竞态、IO故障、owner/epoch回归通过 |
| M3 受限删除 | 确认/epoch复核、白名单删除、部分失败与重试、空间刷新 | 不误删/不并发/不伪全成功，设备手动验证 |
| M4 整体交付 | UI可读性、文档、版本0.5、保留0.4旧包、完整构建、独立只读审查 | 阻塞项关闭，APK/源/审查指纹对齐；交付用户验收，未实测项明确列出 |

每阶段先写/更新测试，再实现，完成后更新三份工作文件。一个writer改生产源码，冻结后独立review，集中修复；不在同一轮叠加模型驻留或推理加速。模型/录音/APK/签名密钥不入Git；commit/push需单独授权。

## 11. 已确认的默认方案（用户授权开始实施）

1. **独立模型管理页面**，从主页和输入法进入；首页移除导入/校验/空间三个操作按钮，仅保留模型摘要与入口。
2. **本版只支持当前固定MNN模型**，没有下载或多模型切换。
3. **前台导入/校验**：离开/锁屏请求取消，旋转不取消；不提供后台持续服务。
4. **文件级恢复**：重试需重新选择目录，完整文件复用，半文件重新复制。
5. **删除只作用于App内副本**，需确认、不提供伪撤销，不清转写文本。
6. **按M1→M4顺序实施**；用户在规划确认后明确“开始”，已授权实现/测试/构建与审查，未授权commit/push或设备操作。
